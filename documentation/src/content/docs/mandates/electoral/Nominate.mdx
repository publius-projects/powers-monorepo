---
title: Nominate
description: Guide for using the Nominate mandate in the Powers protocol
---

The **Nominate** mandate lets any user put themselves forward as a candidate for a role or election — or withdraw their name at any time. It works by updating a shared list of nominees managed by a `Nominees` helper contract.

This mandate is typically the first step in an electoral process. Other mandates, such as `DelegateTokenSelect` or `ElectionList_Vote`, then use that list to run the actual election.

## What it does

When a user calls this mandate, they are either:
- **Adding themselves** to the list of active nominees (`shouldNominate = true`)
- **Removing themselves** from that list (`shouldNominate = false`)

The mandate passes the caller's address directly to the `Nominees` contract — users can only nominate or withdraw themselves, not others.

## Setup

When an organisation adopts this mandate, one configuration value must be provided:

| Parameter | Type | Description |
| :--- | :--- | :--- |
| `NomineesContract` | address | The Nominees contract that holds the list of candidates for this election |

## Calling the mandate

When submitting a request, one input is required:

| Parameter | Type | Description |
| :--- | :--- | :--- |
| `shouldNominate` | bool | `true` to add yourself as a nominee, `false` to withdraw |

## How it works

1. The mandate reads the `shouldNominate` value from the submitted calldata.
2. It looks up the configured `Nominees` contract address.
3. It prepares a call to `Nominees.nominate(callerAddress, shouldNominate)`.
4. The Powers protocol executes that call, updating the nominee list accordingly.
